## The MCG Prototype

**Montgomery County Golf** is a nine-course public county system in Maryland — Falls Road, Northwest,
Hampshire Greens, Laytonsville, Little Bennett, Needwood, The Crossvines, Rattlewood, and Sligo Creek. The prototype is the whole
product assembled around it, and it's the artifact to put in front of a stakeholder when a Storybook story
isn't enough.

Every tab in the global nav works. Browsing is open — nothing is gated — and **any credentials sign you in**.

<TabTable />

### State that carries

The prototype keeps one object in `localStorage`, so a walkthrough behaves like an application rather than a
slide deck:

- **Add to cart** → the nav badge and total update, and the cart survives a refresh
- **Book a tee time or a lesson** → it shows up in **Account → Activity**
- **Buy a lesson package** → credits land in **Account → Wallet** and can be spent at lesson checkout
- **Set county residency** anywhere → every course reprices to the resident rate
- **Account → Settings → Reset prototype data** clears it all for the next demo

### Why it can't drift from this Storybook

Both are built from the same source tree — there is no copy step between them. Each screen's UI lives in
**one file** under `src/components/`, and neither the route nor the story contains any markup of its own:

```
src/components/mcg/tee-times/tee-sheet-screen.tsx     ← the screen (one copy)
        │
        ├── src/app/tee-times/page.tsx                ← the route: a thin wrapper
        └── src/stories/mcg/tee-times.stories.tsx     ← the story: renders the same component
```

Validate a change in either place and the other already has it. The **MCG Prototype** category in the
sidebar is those same screens, story by story.

Two details make it work: `asset()` resolves brand imagery for both hosts (Storybook serves images at the
site root, the prototype from a nested base path), and `useSession()` returns an inert session when no
provider is present, so a component that reads the cart renders unchanged inside a story.

## The Instruction category

**Instruction** is the MCG Academy, and the most recent product work. It answers a live question: whether
Tenfore can replace CoachNow for a 25-instructor county academy. Two flows, built to be argued over:

- **Book a Lesson** — service-first, so privates and multi-week clinics share one catalog and one checkout.
  "Any available instructor" is a first-class choice rather than a fallback, which is the fix for landing on
  one pro's empty calendar and starting over.
- **Packages & Credits** — three pricing models side by side (a credit book, a volume discount, a monthly
  plan), with a **Model Comparison** page scoring them across ten dimensions.

Pricing is one academy menu plus a per-instructor adjustment, not a catalog per pro — see
**Instruction → Elements → Pricing Model** for the argument in one table.

## Multi-club theming & Design Systems

A single helper, `clubBrandStyle(color)`, re-points the brand namespace tokens so an entire screen adopts a
club's color with no per-component edits. The **Design Systems** category showcases this:

- **Colorways** — the full booking style guide rendered in each hue of the utility palette.
- **Color Theory** — analogous, complementary, and triadic harmonies derived from real OKLCH hue.
- **Kettle Hills · Sagamore · FloGolf · MCG** — the live per-club colorways (blue, near-black, green, green).
- **Accessibility** — every brand surface uses the `-700` shade and clears **WCAG AA (4.5:1)**; each guide badges its worst-case contrast.

One known limit: `clubBrandStyle` re-points the mid and solid brand tokens but not the light ones
(`bg-brand-primary` / `bg-brand-secondary` resolve through `--color-brand-50/100` at `:root`), so a
re-skinned club still shows the default ramp's light tints behind selected states.

## Foundations & components

**Foundations** documents the tokens everything is built from — the semantic color system (`text-primary`,
`bg-brand-solid`, `fg-success-primary`, …), the type scale, spacing, radius, and the brand logos for each
golf course. **Components** is the Untitled UI library those tokens dress.

## How it's built

- **React 19** + **TypeScript** throughout
- **Tailwind CSS v4** with a semantic, light/dark-aware token system (`src/styles/theme.css`, `palette.css`)
- **React Aria Components** as the accessibility foundation (imported as `Aria*`)
- **Storybook 10** (`@storybook/nextjs-vite`) for documentation and visual testing
- **Next.js 16** static export for the prototype — both deploy to the same GitHub Pages site in one build

### Running it locally

```bash
npm run storybook   # this library      → http://localhost:6017
npm run dev         # the MCG prototype → http://localhost:3000
npm run build:pages # both, combined exactly as CI publishes them
```

### Conventions

- Files are **kebab-case**; React Aria imports are prefixed **`Aria*`**.
- Style with **semantic tokens** (`text-secondary`, `bg-primary`) — never literal color classes.
- Screens live in `src/components/`; routes and stories are thin wrappers that render them.
